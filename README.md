# NP POS

卓と伝票を中心に、会計・歩合・在庫を扱う日本語のPOSデモです。サンプルデータで、開店、来店、複数卓の連結・移動、注文、延長、前受金と分割会計、退店、閉店を操作できます。

[Webアプリを開く](https://ryo1107sai10.github.io/np-pos/)

## メニュー

画面左上の「メニュー」から、営業、顧客・資金、分析・レポート、スタッフ管理、店舗設定、アカウントを開けます。表示する操作は店舗の権限に応じて変わります。

- 「サンプル操作」から「体験クエスト」を選ぶと、練習専用のデータで開店から日報まで操作できます。「操作ガイド」ではキーワードで手順を探せます。
- 伝票の「注文」に複数の商品を追加し、それぞれに歩合先を指定して一括で確定できます。伝票内の「操作履歴」では来店・注文・延長などの記録を確認できます。
- 「日報」→「会計CSV設定」で日次・伝票別の列と文字コードを変更できます。定型のfreee向け出力も利用できます。「運用設定」では営業日の切替時刻、営業時間、開店準備金の初期値を指定できます。
- 「延長・カード設定」でカードとQRの決済ブランド・加算率を登録できます。「印刷設定」では帳票ごとの明細のまとめ方、支払内訳、店舗控えを設定できます。
- カード・QRの前受金では、会計に充当する額、決済加算、端末で受け取る額を確認できます。マネージャー以上は支払いごとに加算を免除できます。
- 「入出金管理」で入出金を訂正・取消できます。「金庫・出金先」を登録するとレジとの移動も記録できます。「日報」では締め後の実残高を店舗管理者が訂正できます。
- 「給与・支給明細」で勤怠項目、個人別変数、計算式と条件を設定できます。確定明細は給与月と対象キャストを選んで一括印刷または個別PDFのZIPに出力できます。

- 「伝票履歴」では期間・決済方法・状態・席名・顧客名などで検索し、会計内訳を開いたりCSVを出力したりできます。会計取消は取消履歴として確認できます。
- 会計後に同席者の指定漏れや誤りに気づいた場合は、店舗管理者が「同席者を訂正」で理由を入力し、追加・解除できます。来店履歴と監査ログに反映します。
- 「経営分析」「商品別売上」では日報と同じ確定売上を使い、客単価、決済、商品別売上、キャスト成績を期間指定で確認できます。商品別の金額は値引きとサービス料を加味する前の注文金額です。CSV出力とA4印刷に対応しています。
- 「サンプル操作」→「滞在・指名分析を試す」で、指名あり・なしの売上、客単価、滞在時間を2営業日分のサンプルで比較できます。滞在は来店から退店までの記録で集計します。退店前の伝票と、旧データで明細や時刻が欠けている伝票は計測数に含めず、日別CSVでも確認できます。
- 「スタッフ成績」は、会計を確定したマネージャー・スタッフごとの件数と税込金額を集計します。操作者が保存されていない旧伝票は未記録として集計します。
- 未会計の伝票では営業メモを残せます。マネージャー以上は理由を添えて終了時刻を調整できます。変更は監査ログに残ります。
- 「営業のお知らせ」で在庫の下限を確認し、「操作ガイド」で開店からレジ締めまでの手順を確認できます。
- 店舗管理者は「時間帯別セット」で、来店登録時に提案する初回セットを日本時間の時間帯ごとに設定できます。翌日にまたがる時間帯を登録でき、来店時の手動変更と設定ファイルでの移行にも対応します。

## シフト・給与・日払い

「勤怠・人件費」では役職・勤務者・営業日ごとの勤務実績と人件費参考額を確認し、人件費・日別勤怠をCSVで保存できます。管理者が勤務者と適用開始日付きの時給を登録し、管理者またはマネージャーが「勤怠」で出退勤を記録します。キャストは既存の勤怠・給与情報から集計します。日報と経営分析にも役職別の集計が表示されます。「サンプル操作」→「勤怠・人件費を試す」で、時給未登録と0円の違いを確認できます。

「シフト」では店舗管理者とマネージャーが勤務希望と確定シフトを登録し、日別・週別・月別に確認できます。日をまたぐ勤務も登録できます。シフトは勤務予定です。給与の実働時間は承認した打刻から集計し、下書きから営業日単位で調整できます。

給与の計算式では、確定個人売上、勤務日数、記録した遅刻・欠勤・無断欠勤日数、商品・分類別の担当数量・個人売上・確定歩合・ポイントを参照できます。分類は注文時に記録された名称、複数人で担当した商品は人数で分けた数量を使います。使用した実績値と計算ルールは明細の確定時に保存されます。デモでは「給与・日払いを試す」から「計算テンプレート」を開き、美月に「実績連動サンプル」を割り当てると試算で確認できます。

「給与・支給明細」は店舗管理者のみ開けます。適用開始日付きの時給、確定歩合、ポイント換金、手当・控除、支給済みの日払いを合算します。「日付指定で集計」は、月をまたぐ期間でも勤怠・確定歩合を営業日、日払いを実際の支給日で集計します。時給・歩合・ポイントの換金額は、選択期間の分を給与月ごとに丸めてから合算します。集計後にキャストを複数選び、期間の参考明細を個人別PDFのZIPで保存できます。日付のない手当・控除や月次テンプレートの計算は、月次明細で確認できます。確定した明細はA4で印刷でき、月と対象者の範囲を指定して個人別PDFをZIPで保存できます。確定後は本人のマイページに給与のお知らせが表示されます。既読は利用中のブラウザーに記録します。

日払いはキャスト本人または店舗管理者が申請を登録し、店舗管理者が承認または却下し、支給を記録します。現金支給はレジからの出金として記録します。日報とCSVで現金・振込を確認できます。「サンプル操作」→「給与・日払いを試す」では勤務3時間の下書き、日払い申請、当月・前月の確定明細を確認できます。

## 操作ガイドとAI操作アシスト

「操作ガイド」で、「レシートを印刷したい」などのキーワードから、権限に合った手順と画面を探せます。デモでも使えます。

クラウド店舗でAIによる手順整理を有効にする場合は、Workerに `OPENAI_API_KEY` をシークレットとして登録し、`OPENAI_GUIDE_MODEL` と対象の `OPENAI_GUIDE_STORE_IDS`（複数の場合はカンマ区切り）を設定します。設定した店舗ではガイド内の「AIで手順を見る」を使えます。OpenAIへ渡すのは選択された項目の既定のマニュアル文章です。利用枠は店舗あたり日本時間の1日30件です。

## クラウド店舗を使う

1. 「クラウドにサインイン」を開き、メールアドレスでアカウントを作成します。確認メールのリンクを開くと、店舗の作成や招待された店舗への参加ができます。
2. 管理者は店舗を作成し、「このブラウザーから移行」か「新しい営業データで始める」を選びます。移行は営業データが未登録の店舗で行い、卓・店舗設定・伝票・入出庫・締めと歩合の履歴をコピーします。元のブラウザーの保存データも残ります。
3. 別の端末でも同じ公開ページにサインインし、店舗を選択します。スタッフには「メンバーと権限」から、確認済みにするメールアドレスを指定して招待を登録します。シフトに入る人は同じ公開ページで招待先のメールアドレスを使います。
4. アカウント画面の「デモを開く」でサインイン不要のサンプルへ戻れます。デモの操作はブラウザー内のデモデータに保存されます。

店舗管理者は設定変更、移行、招待、権限の変更と解除ができます。マネージャーは営業・値引き・締めの操作ができ、自分が登録した顧客の詳細を扱えます。スタッフはホールで来店・注文・会計などを操作できます。キャストは「マイページ」で本人の勤務・支給明細を確認できます。

PCとスマホは店舗ごとの保存先を共有します。通信断中の注文・会計などはブラウザー内の送信待ちに保存し、再読み込み後も同じアカウント・店舗で接続すると順番に送信します。「送信待ちを確認」で内訳と競合を確認できます。送信待ちの注文がある伝票の会計は、同期後に金額を確認して進めます。競合時は当該操作と後続を保留し、最新の営業データを確認してからやり直せます。


### キャスト本人のアカウントと店舗の確認

「店舗・アカウント」からキャスト権限で招待し、相手が確認済みメールで店舗に参加したら、「メンバーと権限」で登録済みのキャストをひもづけます。本人のマイページでは、勤務希望・日払い申請、出退勤の打刻、支給明細の閲覧とPDF保存ができます。退勤時に休憩分を入力し、店舗管理者またはマネージャーが「勤怠」で実働時間を確認します。

複数の店舗で管理者権限を持つ場合は「複数店舗の営業状況」で各店舗の直近の営業日と月間売上を確認できます。
メニューの「店舗グループ」では、自分が作成した店舗をまとめ、マネージャーまたはスタッフを確認済みメールアドレスで招待できます。グループから外した店舗やメンバーのグループ経由のアクセスは解除され、店舗から直接付与された権限は引き続き有効です。サインインせずに開くと、サンプル店舗で登録・招待・権限切り替えを試せます。
店舗の「メンバーと権限」でアクセスを解除すると、その店舗の直接権限とグループ経由のアクセスが停止します。グループの他店舗の権限は保たれます。店舗を作成した管理者は、グループ権限での復帰や、役職を指定した再招待を行えます。

「役職・権限」では、マネージャー・スタッフを基に店舗独自の役職を作れます。注文、延長、会計、印刷、在庫更新、レポート、勤怠編集などを個別に許可し、「メンバーと権限」で店舗メンバーに割り当てます。基にした役職の権限が上限です。デモでは役職を保存してから「サンプル操作」で切り替えられます。

店舗管理者は「税・サービス料」から税込／税抜、サービス料率、値引き前後の計算基準、端数処理を指定できます。計算設定は保存後に登録する来店から適用します。個別商品の税率とサービス料の対象は「店舗設定」で変更でき、商品設定は次に追加した明細から適用します。

「税・サービス料」で「注文明細ごとのサービス料除外を許可する」をオンにすると、店舗管理者は注文時に「この明細にサービス料をかけない」を選び、理由とともに登録できます。会計前の明細は「訂正」から切り替えできます。サービス料を除いた伝票見込額を確認でき、変更と理由は操作履歴に残ります。許可をオフにしても登録済みの明細には引き続き同じ計算が適用されます。

## 値引き・会計の訂正・監査ログ

- マネージャー以上は、営業中の伝票詳細で「個人売上を調整」を開き、キャストと増減額、理由を記録できます。会計額や歩合支給額を変えずに、個人売上と監査ログへ反映します。値引き登録時に個人売上への反映も選べます。
- 伝票の「値引き」で金額または率を入力し、理由区分と詳しい理由を保存します。管理者は「日報」→「運用設定」でマネージャーの上限を変更できます。初期値は税抜小計の10%です。上限を超える申請は管理者が伝票上で承認または却下します。承認待ちは会計を止めます。
- 営業中の当日会計を訂正するには、管理者が「会計内訳」から「会計を取り消す」を選びます。確定売上・歩合・支払記録を取り消し、注文時に引いた在庫を戻します。元の会計は「日報」の「会計取消の履歴」から開けます。実際の返金は受け付けた決済手段で行います。
- 「会計取消の履歴」で伝票を開き、空席と理由を指定して再オープンできます。注文と値引きを引き継いだ未会計の伝票になり、在庫を引き直します。
- 会計後の支払内訳は、店舗管理者が伝票詳細または「日報」→「会計履歴」の「支払方法を訂正」で変更できます。会計合計・前受金・会計時のカード加算を保ち、訂正先の現金・カード・QR決済の金額と理由を指定します。日報の決済別集計、レジ理論残高、締め差額に反映します。締め時に数えた実残高は保持します。
- 管理者は「日報」→「監査ログ」で、記録時刻・操作者・対象・変更前後・理由を確認できます。デモでは「サンプル操作」から管理者・マネージャー・スタッフを切り替えて、同じ伝票の申請と承認を試せます。

営業中のサンプルでは、B-02 の会計済み伝票で現金をカードに訂正できます。

## 顧客管理

1. ホールの「来店登録」で検索すると、登録済みの顧客を選択できます。顧客を指定せず来店を登録することもできます。新規顧客は「顧客管理」で登録します。未会計の伝票は、伝票詳細の「顧客を設定」で登録済み顧客を検索し、ひもづけ・変更・解除できます。来店と指名の履歴は保存後の顧客に反映します。顧客詳細で来店・指名履歴、累計売上、キープボトルを確認できます。管理者は顧客のCSV一括登録、重複の統合、過去の伝票とのひもづけもできます。
2. 会計後は、店舗管理者が伝票詳細または日報の会計内訳で「顧客を訂正」を選び、登録済みの顧客と訂正理由を保存します。監査ログで訂正前後・理由・操作者・日時を確認できます。
3. 顧客の編集で年ごとに繰り返す記念日を月日と名前で登録できます。「顧客管理」と「営業のお知らせ」には、営業日から7日先までの誕生日・記念日、期限が近いか過ぎている残量ありのボトルが表示されます。「サンプル操作」→「顧客のお知らせを試す」で確認できます。

## 入出金管理と日報

1. 開店時に釣銭準備金を入力します。営業中は「入出金管理」→「入出金を記録」から、入金・出金・経費、金額、理由区分と具体的な理由を保存します。移動先・支払先も記録できます。
2. 日報には売上、組数、客数、客単価、決済別の会計入金、前受金の受領・充当が営業日ごとに表示されます。入出金管理では、日時、理由、相手先、担当者を確認できます。
3. レジの理論残高は、釣銭準備金に、現金会計・現金前受金・その他の現金入金を加え、出金と経費を引いた金額です。会計時に充当した前受金は受領時に計上済みです。
4. 「閉店処理」で数えたレジの実残高を入力します。差がある場合は理由を入力してから確定します。実残高、理論残高、差額、理由は日報に保存されます。入出金の登録と閉店処理はマネージャーまたは店舗管理者が操作できます。

「サンプル操作」→「入出金と日報を試す」で、その他の現金入金と経費を含むレジの理論残高が¥29,000のサンプルを開けます。デモの店舗設定と履歴がサンプルの初期状態に戻ります。

## 会計確認伝票・レシート・領収書を印刷する

1. 会計前は、ホールで卓を選び、伝票詳細の「確認伝票を印刷」を押します。明細・税込合計・前受金を差し引いた支払予定額を確認できます。
2. 会計後は「会計内訳」で「レシートを印刷」か「領収書を印刷」を選びます。退店後は日報の会計履歴から開けます。領収書には宛名と但し書きを入力します。領収金額は会計までに受け取った支払額です。
3. プレビューで58mm・80mmを選び、「印刷する」を押します。ブラウザーの印刷画面でもプリンターと用紙幅を指定します。同じ会計の同じ書類を再度発行すると「再発行」が印字されます。発行回数は印刷を指示した時点で記録されます。
4. 管理者は「日報」→「印刷設定」で既定の用紙幅、店名・住所・電話番号・登録番号、明細の表示、会計確定時のレシート自動印刷を設定できます。

「サンプル操作」→「営業中のサンプルを読み込む」で、利用中のA-01と、会計済みのB-02から印刷を試せます。

## 日報の期間指定とCSV

- 「日報」で「日別」「月別」「任意期間」を選びます。開始日と終了日を含む営業日を集計します。期間の一覧から日付を開くと、内訳と会計履歴を確認できます。ホールの「月間売上」は、表示している営業日が属する月の確定売上です。
- 「日報CSV」は営業日ごとに、税込売上、決済別の入金、経費、締め結果を保存します。従来の入金合計のみが保存されている日も出力できます。
- freee向けCSVは売上仕訳の16列・UTF-8 BOM形式です。「日次集計」は営業日ごとに仕訳をまとめ、「伝票別」は会計ごとの仕訳に分けます。同じ売上を取り込むときは片方を選びます。仕訳は会計時に記録された取引を使用します。経費は日報CSVで確認できます。
- freee会計の「取引入力」→「振替伝票」→「インポート」→「他社会計ソフトインポート」から読み込みます。金額は内税（税込）です。出力する勘定科目は会計時の取引に従います。取込画面で科目・税区分・金額を確認してください。[freee公式の取込手順](https://support.freee.co.jp/hc/ja/articles/204847430)
- 売上のある営業日に確定伝票や税率別内訳が残っていない場合は、freee向けCSVの出力を止めます。日報CSVで保存済みの集計を確認できます。

「サンプル操作」→「期間集計とCSVを試す」で、売上合計46,200円、経費900円を含む3営業日分のサンプルを表示します。デモの店舗設定と履歴はサンプルの初期状態に戻ります。

## 自動延長とカード会計加算

ホールの「延長・カード設定」から、店舗管理者が項目ごとにオン・オフを切り替えて保存します。初期状態はどちらもオフです。

- 自動延長をオンにして、適用する延長プランを選びます。卓の設定は、ホールの「卓別の自動延長」または利用中の伝票詳細にある「卓の自動延長」から変更できます。店舗全体がオンのとき、卓ごとの設定が適用されます。設定は次の来店にも引き継ぎ、連結中はすべての卓がオンのときだけ延長します。
- 自動延長まで1分以内になると、ホールに卓名と残り時間が表示されます。通知から「今回の来店だけ自動延長を止める」または「会計へ進む」を選べます。会計へ進むと今回の自動延長を止めて会計画面を開きます。会計を閉じても今回の停止は有効です。すでに計上した延長料金と卓の設定は引き継ぎます。伝票詳細の「自動延長を再開」で今回の停止を解除できます。停止中の料金はさかのぼって加算しません。終了時刻を過ぎている場合は、再開してから延長プランの時間が経過した時点で追加します。次の来店には卓の設定が適用されます。クラウド店舗では端末の同期時に延長を反映します。
- カード会計加算をオンにして、税込の加算率を設定します。分割会計では、カードで支払う加算前の額にだけ掛けて、円単位で四捨五入します。会計画面に表示される「カード端末の決済額」を使います。加算額は確定後のレシートと日報・売上CSVにも反映されます。ご利用の決済契約でカード加算が認められている場合に有効にしてください。 [JCB加盟店のお取り扱いガイド](https://www.jcb.co.jp/merchant/pop/pdf/jcb-merchant-guide.pdf)

「サンプル操作」→「自動延長とカード会計を試す」で、A-01の通知と約30秒後の延長を確認できます。A-02はオフです。カード会計加算は5%です。デモの設定と履歴はサンプルの初期状態に戻ります。

同じサンプルで、ホールの「A-02」→「注文」→「ハイボール」→「この明細にサービス料をかけない」の順に選ぶと、伝票見込額を確認できます。理由を入力して「注文を確定」し、伝票の「操作履歴」で記録を確認できます。

利用中の伝票では、管理者・マネージャーが「人数を変更」で訂正・途中合流・一部退店を記録できます。既存の料金はそのまま、以降の延長は変更後の人数で計算します。時間を過ぎた卓では「超過分を一括延長」で選んだプランの延長回数と金額を確認できます。通常の「延長」では、選んだプランと前受金を反映した「延長見積書」を58mm・80mmで印刷できます。

## サンプル操作

1. 左下の「サンプル操作」から「開店から試す」を選びます。
2. 釣銭準備金を確認して開店し、空卓に来店を登録します。複数の卓を選ぶと同じ伝票を共有します。
3. 「キャストドリンク」を注文してキャストを選ぶと、在庫と歩合見込に反映されます。
4. 延長、会計、退店の後に閉店します。会計を確定した歩合と締め結果は各画面から確認できます。

デモの操作履歴はブラウザー内に保存されます。カード・QR決済の操作はサンプルの支払記録です。

- 現金会計では、お客様から受け取った額を入力するとお釣りを計算します。「閉店処理」の「金種別に数える」で実残高を計算し、金種と枚数を日報に残せます。
- 「給与・支給明細」の「計算テンプレート」で手当・控除の設定を保存し、キャストごとに適用できます。時給の未登録で試算が保留の場合は、対象営業日を確認して「時給を登録」を選びます。

## 店内レイアウトを編集する

1. ホールの「レイアウト編集」を開きます。「フロア・エリアを追加」から店内の区画を作れます。既存の区画は選択して名前を変更できます。卓がひとつも残っていない区画は「エリアを削除」から整理できます。
2. 「卓を追加」で選択中の区画に卓を作れます。卓を選ぶと、卓名、エリア、横・縦の位置、定員を編集できます。ドラッグや矢印キーでも位置を調整できます。
3. 空いている卓は「卓を削除」から整理できます。利用中・退店待ちの卓は削除できません。削除した卓の名前は伝票履歴で参照できます。
4. 「レイアウトを保存」を押すと、ブラウザー内に保存されます。ホールの「一覧」「レイアウト」で表示を切り替えられます。スマホでは図面の中を左右にスワイプできます。

配置の重なりと、利用客数を下回る定員変更は保存できません。来店グループの使用卓は、伝票の「卓移動・連結」から変更できます。「開店から試す」でも保存した卓と区画を使えます。

## メニュー・料金・歩合を設定する

1. ホールの「店舗設定」で「メニュー」「セット・延長」「キャスト歩合」を開きます。商品、料金プラン、キャストを追加したり、注文画面の選択肢から外したりできます。
2. メニューでは価格と標準歩合を、セット・延長では1人あたりの料金と時間を設定します。既存の在庫品目にひもづける商品は、1点あたりの使用量を設定できます。延長時の指名料も設定できます。
3. キャストの個別歩合は、固定額・売上歩合率・ポイントを設定できます。空欄の項目は商品ごとの標準設定を使います。複数人に付ける場合は、売上・固定額・ポイントを人数で按分します。
4. 「店舗設定を保存」を押します。変更した料金と歩合は、保存後に追加する明細から適用されます。
5. 商品・プラン・キャストを今後の選択肢から外すには、表示の設定をオフにします。削除する場合は対象を選び、削除を確認してから「店舗設定を保存」を押します。利用中や退店待ちの伝票にひもづく項目は削除できません。

「日報」と「歩合・成績」は、営業日を選んで確認できます。会計と歩合は登録時の商品名、単価、歩合条件を使います。確定歩合は会計済みの伝票、見込み歩合は未会計の伝票から集計します。

## 在庫品目を設定する

1. 在庫画面の「品目設定」または店舗設定の「在庫品目」を開きます。「品目を追加」から品目名、単位、仕入原価、在庫の下限を設定できます。登録済みの品目も選んで編集できます。
2. 「メニュー」で商品を選び、「在庫連動」で商品1点につき使う数量を入力して保存します。追加したばかりの品目も同じ編集画面で選べます。
3. 新しく追加した品目の在庫数は0から始まります。在庫画面の「調整」で仕入れごとの単価付き入庫、廃棄・破損、店舗消費を記録できます。「棚卸」では数えた実数を登録し、差がゼロの場合も履歴を残せます。
4. 一覧から外すには、品目設定で「在庫一覧に表示する」をオフにして保存します。在庫画面の「非表示を含む」で残高を確認できます。非表示中も在庫の集計と既存メニューからの引き落としは続きます。
5. 品目の削除は、在庫が0で、メニューの在庫連動と、取消時に在庫を戻す可能性がある未提供の注文へのひもづけが解消された場合にできます。「品目を削除」を選んで確認し、「店舗設定を保存」を押します。過去の入出庫履歴からは、記録時の品目名と単位を確認できます。

品目設定と在庫一覧で「読み取る」を選ぶと、カメラからバーコードを入力できます。在庫一覧では登録済みのコードと一致する品目を表示します。カメラの利用はブラウザーで許可し、コードは手入力もできます。

仕入原価は補充で在庫を増やすときに使います。現在庫の評価額は、記録した入出庫に基づいて計算されます。単位名を編集すると表示が変わり、在庫数とメニューの使用量は入力済みの数値を引き継ぎます。

## PCとスマホで店舗設定とレイアウトを使う

1. PCのホールで編集内容を保存し、「設定の移行」から「設定を書き出す」を選びます。
2. 書き出した `.json` ファイルをスマホへ移し、スマホのホールで「設定の移行」を開きます。
3. ファイルを選び、表示された項目数を確認して「この設定を読み込む」を選びます。

サインインなしで、メニュー・料金・歩合・在庫品目・在庫連動の設定と卓レイアウトを移行できます。在庫品目は非表示の設定も含まれ、ファイルに含まれる品目を読み込み先で更新します。読み込み先の在庫数と入出庫履歴はそのブラウザーで引き継ぎ、移行によって追加される品目は在庫数0から始まります。以前に書き出した店舗設定ファイルとレイアウトファイルも読み込めます。初めて使うブラウザーでは開店前の状態から始めます。利用中や退店待ちの卓がある端末では、これらの卓を外す配置の読み込みを防ぎます。

## デモデータのバックアップと復元

「メニュー → デモデータのバックアップ」で設定と営業データをJSONに保存できます。復元はファイルを選び、保存日時と営業日を確認してから実行してください。現在のデモデータが置き換わります。ファイルには顧客・伝票・在庫・給与・監査履歴が含まれるため、保存先の共有範囲を確認してください。復元はデモを開いているブラウザーに適用されます。

## クラウド保存の復元検証

Node.jsとWranglerを利用できる開発環境で `npm --prefix server run verify:restore` を実行すると、架空の店舗を入れたローカルD1のSQLバックアップを別のD1へ復元します。保存断片をまたぐ日本語データ、閉店した伝票と在庫、確定給与、監査ログ、独自役職、店舗アクセス停止、会計操作の再送を照合します。検証用のデータとDBは終了時に削除されます。

本番DBにはCloudflare D1のTime Travelが適用されます。復元ポイントの保持期間は契約プランに従います。実際の復元時は、接続先と対象時刻を照合し、営業中の書き込みと端末の送信待ちを整理してから切り替えます。D1を復元すると、同じデータベース内の全店舗がその時点に戻ります。FirebaseのアカウントとWorkerのシークレットは別に管理します。[Cloudflare D1の復元手順](https://developers.cloudflare.com/d1/reference/time-travel/)

## ソースを編集する

- `docs/index.html` と `docs/app.mjs` が画面と操作です。
- `docs/style.css` と `docs/clarity.css` が画面のスタイルです。歩合・在庫・営業レポートの表示は `docs/reports.mjs` と `docs/reports.css` にあります。
- `docs/engine.mjs` が卓と伝票の状態管理、会計、歩合、在庫のロジックです。
- `docs/floor-layout.mjs` と `docs/floor-layout.css` が店内レイアウトの表示と編集です。設定の移行画面は `docs/layout-transfer.mjs` と `docs/layout-transfer.css` にあります。
- `docs/store-settings.mjs` が店舗設定の検証と更新を行います。編集画面は `docs/store-settings-editor.mjs` と `docs/store-settings.css` にあります。

ローカルで確認するには、リポジトリのルートで次を実行し、ブラウザーで `http://localhost:8000/` を開きます。

```sh
python3 -m http.server 8000 --directory docs
```

会計・歩合・在庫とクラウドのテストは Node.js 24 で実行できます。

```sh
npm --prefix server ci
node --test tests/*.test.mjs server/*.test.mjs
```

GitHub Pages は `main` の `docs/` を配信します。`docs/cloud-config.mjs` はブラウザー向けのFirebase設定とクラウドAPIの接続先です。Workerは `server/` のAPIでFirebaseのログイン情報と店舗・グループの権限を検証し、D1に保存します。`server/schema.sql` が初期テーブル定義で、`wrangler.jsonc` がWorkerの接続設定です。既存のD1では、Workerを更新する前に `server/migrations/` の `20261117-store-groups.sql`、`20261117-guide-assistant.sql`、`20261117-store-access-blocks.sql`、`20261117-custom-store-roles.sql` を順に適用してください。
