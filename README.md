# NP POS

卓と伝票を中心に、会計・歩合・在庫を扱う日本語のPOSデモです。サンプルデータで、開店、来店、複数卓の連結・移動、注文、延長、前受金と分割会計、退店、閉店を操作できます。

[Webアプリを開く](https://ryo1107sai10.github.io/np-pos/)

## クラウド店舗を使う

1. 「クラウドにサインイン」を開き、メールアドレスでアカウントを作成します。確認メールのリンクを開くと、店舗の作成や招待された店舗への参加ができます。
2. 管理者は店舗を作成し、「このブラウザーから移行」か「新しい営業データで始める」を選びます。移行は営業データが未登録の店舗で行い、卓・店舗設定・伝票・入出庫・締めと歩合の履歴をコピーします。元のブラウザーの保存データも残ります。
3. 別の端末でも同じ公開ページにサインインし、店舗を選択します。スタッフには「メンバーと権限」から、確認済みにするメールアドレスを指定して招待を登録します。シフトに入る人は同じ公開ページで招待先のメールアドレスを使います。
4. アカウント画面の「デモを開く」でサインイン不要のサンプルへ戻れます。デモの操作はブラウザー内のデモデータに保存されます。

店舗管理者は設定変更、移行、招待、権限の変更と解除ができます。マネージャーは営業・値引き・締めの操作ができ、顧客名は担当伝票で確認できます。スタッフはホールで来店・注文・会計などを操作できます。キャストと体入のアカウントには所属店舗を表示します。

PCとスマホは店舗ごとの保存先を共有します。送信待ちの表示中は、その画面で同期の結果を確認してください。別の端末の更新と競合した操作は、最新状態を確認してやり直せます。

## サンプル操作

1. 左下の「サンプル操作」から「開店から試す」を選びます。
2. 釣銭準備金を確認して開店し、空卓に来店を登録します。複数の卓を選ぶと同じ伝票を共有します。
3. 「キャストドリンク」を注文してキャストを選ぶと、在庫と歩合見込に反映されます。
4. 延長、会計、退店の後に閉店します。会計を確定した歩合と締め結果は各画面から確認できます。

デモの操作履歴はブラウザー内に保存されます。カード・QR決済の操作はサンプルの支払記録です。

## 店内レイアウトを編集する

1. ホールの「レイアウト編集」を開きます。「フロア・エリアを追加」から店内の区画を作れます。既存の区画は選択して名前を変更できます。卓がひとつも残っていない区画は「エリアを削除」から整理できます。
2. 「卓を追加」で選択中の区画に卓を作れます。卓を選ぶと、卓名、エリア、横・縦の位置、定員を編集できます。ドラッグや矢印キーでも位置を調整できます。
3. 空いている卓は「卓を削除」から整理できます。利用中・退店待ちの卓は削除できません。削除した卓の名前は伝票履歴で参照できます。
4. 「レイアウトを保存」を押すと、ブラウザー内に保存されます。ホールの「一覧」「レイアウト」で表示を切り替えられます。スマホでは図面の中を左右にスワイプできます。

配置の重なりと、利用客数を下回る定員変更は保存できません。来店グループの使用卓は、伝票の「卓移動・連結」から変更できます。「開店から試す」でも保存した卓と区画を使えます。

## メニュー・料金・歩合を設定する

1. ホールの「店舗設定」で「メニュー」「セット・延長」「キャスト歩合」を開きます。商品、料金プラン、キャストを追加したり、注文画面の選択肢から外したりできます。
2. メニューでは価格と標準歩合を、セット・延長では1人あたりの料金と時間を設定します。既存の在庫品目にひもづける商品は、1点あたりの使用量を設定できます。延長時の指名料も設定できます。
3. キャストの個別歩合は、固定額・売上歩合率・ポイントを設定できます。空欄の項目は商品ごとの標準設定を使います。複数人に付ける場合は、売上・固定額・ポイントを人数で按分します。
4. 「店舗設定を保存」を押します。変更した料金と歩合は、保存後に追加する明細から適用されます。
5. 商品・プラン・キャストを今後の選択肢から外すには、表示の設定をオフにします。削除する場合は対象を選び、削除を確認してから「店舗設定を保存」を押します。利用中や退店待ちの伝票にひもづく項目は削除できません。

「営業レポート」と「歩合・成績」は、営業日を選んで確認できます。会計と歩合は登録時の商品名、単価、歩合条件を使います。確定歩合は会計済みの伝票、見込み歩合は未会計の伝票から集計します。

## 在庫品目を設定する

1. 在庫画面の「品目設定」または店舗設定の「在庫品目」を開きます。「品目を追加」から品目名、単位、仕入原価、在庫の下限を設定できます。登録済みの品目も選んで編集できます。
2. 「メニュー」で商品を選び、「在庫連動」で商品1点につき使う数量を入力して保存します。追加したばかりの品目も同じ編集画面で選べます。
3. 新しく追加した品目の在庫数は0から始まります。在庫画面の「調整」から仕入れや棚卸による増減を記録できます。
4. 一覧から外すには、品目設定で「在庫一覧に表示する」をオフにして保存します。在庫画面の「非表示を含む」で残高を確認できます。非表示中も在庫の集計と既存メニューからの引き落としは続きます。
5. 品目の削除は、在庫が0で、メニューの在庫連動と、取消時に在庫を戻す可能性がある未提供の注文へのひもづけが解消された場合にできます。「品目を削除」を選んで確認し、「店舗設定を保存」を押します。過去の入出庫履歴からは、記録時の品目名と単位を確認できます。

仕入原価は補充で在庫を増やすときに使います。現在庫の評価額は、記録した入出庫に基づいて計算されます。単位名を編集すると表示が変わり、在庫数とメニューの使用量は入力済みの数値を引き継ぎます。

## PCとスマホで店舗設定とレイアウトを使う

1. PCのホールで編集内容を保存し、「設定の移行」から「設定を書き出す」を選びます。
2. 書き出した `.json` ファイルをスマホへ移し、スマホのホールで「設定の移行」を開きます。
3. ファイルを選び、表示された項目数を確認して「この設定を読み込む」を選びます。

サインインなしで、メニュー・料金・歩合・在庫品目・在庫連動の設定と卓レイアウトを移行できます。在庫品目は非表示の設定も含まれ、ファイルに含まれる品目を読み込み先で更新します。読み込み先の在庫数と入出庫履歴はそのブラウザーで引き継ぎ、移行によって追加される品目は在庫数0から始まります。以前に書き出した店舗設定ファイルとレイアウトファイルも読み込めます。初めて使うブラウザーでは開店前の状態から始めます。利用中や退店待ちの卓がある端末では、これらの卓を外す配置の読み込みを防ぎます。

## ソースを編集する

- `docs/index.html` と `docs/app.mjs` が画面と操作です。
- `docs/style.css` と `docs/clarity.css` が画面のスタイルです。歩合・在庫・営業レポートの表示は `docs/reports.mjs` と `docs/reports.css` にあります。
- `docs/engine.mjs` が卓と伝票の状態管理、会計、歩合、在庫のロジックです。
- `docs/floor-layout.mjs` と `docs/floor-layout.css` が店内レイアウトの表示と編集です。設定の移行画面は `docs/layout-transfer.mjs` と `docs/layout-transfer.css` にあります。
- `docs/store-settings.mjs` が店舗設定の検証と更新を行います。編集画面は `docs/store-settings-editor.mjs` と `docs/store-settings.css` にあります。

ローカルで確認するには、リポジトリのルートで次を実行し、ブラウザーで `http://localhost:8000/` を開きます。

```sh
python3 -m http.server 8000 --directory docs
```

会計・歩合・在庫とクラウドのテストは Node.js 24 で実行できます。

```sh
npm --prefix server ci
node --test tests/*.test.mjs server/*.test.mjs
```

GitHub Pages は `main` の `docs/` を配信します。`docs/cloud-config.mjs` はブラウザー向けのFirebase設定とクラウドAPIの接続先です。Workerは `server/` のAPIでFirebaseのログイン情報と店舗メンバーの権限を検証し、D1に保存します。`server/schema.sql` が初期テーブル定義で、`wrangler.jsonc` がWorkerの接続設定です。
